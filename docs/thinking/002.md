1. Responsabilidade da pasta memory

A pasta não deveria conhecer detalhes do agente.

Por exemplo, o agente deveria conseguir fazer:

memory.remember(
    user_id="123",
    content="O usuário prefere respostas curtas."
)


e depois:

memories = memory.recall(
    user_id="123",
    query="Quais são as preferências desse usuário?"
)


Assim, o agente não precisa saber se estamos usando PostgreSQL, Redis, Qdrant, pgvector, SQLite ou outro mecanismo.

3. Criar uma interface para o Storage

O ponto mais importante da arquitetura é não deixar o MemoryManager dependente diretamente do banco.

store.py:

from abc import ABC, abstractmethod
from typing import List, Optional

from .models import Memory


class MemoryStore(ABC):

    @abstractmethod
    async def save(self, memory: Memory) -> Memory:
        pass

    @abstractmethod
    async def get(self, memory_id: str) -> Optional[Memory]:
        pass

    @abstractmethod
    async def delete(self, memory_id: str) -> None:
        pass

    @abstractmethod
    async def list(
        self,
        user_id: str,
        limit: int = 20
    ) -> List[Memory]:
        pass


Isso permite futuramente:

MemoryStore
    │
    ├── PostgreSQLMemoryStore
    ├── SQLiteMemoryStore
    ├── RedisMemoryStore
    └── ...


Sem precisar alterar o restante da aplicação.

4. Retrieval

A recuperação das memórias deve ser uma responsabilidade separada.

retrieval.py:

from abc import ABC, abstractmethod
from typing import List

from .models import Memory


class MemoryRetriever(ABC):

    @abstractmethod
    async def search(
        self,
        user_id: str,
        query: str,
        limit: int = 5
    ) -> List[Memory]:
        pass


Posteriormente podemos implementar:

MemoryRetriever
       │
       ├── VectorRetriever
       ├── KeywordRetriever
       └── HybridRetriever


Eu recomendaria HybridRetriever para uma arquitetura mais completa:

                   Top Memories

6. MemoryManager

Essa será a principal API utilizada pelo restante do sistema.

from .models import Memory
from .store import MemoryStore
from .retrieval import MemoryRetriever


class MemoryManager:

    def __init__(
        self,
        store: MemoryStore,
        retriever: MemoryRetriever,
    ):
        self.store = store
        self.retriever = retriever

    async def remember(
        self,
        user_id: str,
        content: str,
        memory_type: str = "semantic",
        importance: float = 0.5,
        metadata: dict | None = None,
    ) -> Memory:

        memory = Memory(
            id=self._generate_id(),
            user_id=user_id,
            content=content,
            memory_type=memory_type,
            importance=importance,
            metadata=metadata,
            created_at=self._now(),
        )

        return await self.store.save(memory)

    async def recall(
        self,
        user_id: str,
        query: str,
        limit: int = 5,
    ):
        return await self.retriever.search(
            user_id=user_id,
            query=query,
            limit=limit,
        )


A aplicação fica extremamente simples:

memories = await memory.recall(
    user_id=user_id,
    query=user_message,
)

9. Separar Short-Term e Long-Term Memory

Eu também criaria dois níveis.

                    MEMORY
                       │
          ┌────────────┴────────────┐
          │                         │
          ▼                         ▼
   Short-Term Memory        Long-Term Memory
          │                         │
     Contexto atual            Memórias
     da conversa              persistentes
          │                         │
          ▼                         ▼
       Redis                  PostgreSQL
                                +
                              pgvector

Short-Term

Informações necessárias durante a conversa atual.

Exemplo:

Usuário:
"Quero criar uma API."

Depois:
"Faça ela usando FastAPI."

Depois:
"Agora adicione autenticação."


O sistema precisa saber que "ela" refere-se à API criada anteriormente.

Long-Term

Informações que devem sobreviver à conversa:

Usuário prefere Python.
Usuário trabalha com FastAPI.
Usuário prefere respostas em português.
Usuário está construindo um sistema de agentes.

O Agent não conhece o banco. O Agent conhece apenas o MemoryManager.

Isso deixa a arquitetura preparada para evoluir de um MVP para um sistema de memória de agentes mais robusto sem precisar reescrever a aplicação inteira.
