02. AGENTS.md global

O AGENTS.md da raiz é o contrato global.

Ele deve definir coisas que todos os agentes precisam respeitar.

# AGENTS.md

## Objetivo

Este repositório utiliza uma arquitetura multiagente.

Os agentes possuem responsabilidades específicas e devem trabalhar
de forma coordenada através de delegação, handoff, skills e memória.

## Hierarquia

CEO
├── Developer
├── Researcher
└── Reviewer

O CEO é responsável pela coordenação.

Agentes especializados não devem assumir responsabilidades de outros
agentes sem autorização explícita.

## Regras gerais

1. Ler este arquivo antes de executar qualquer tarefa.
2. Ler o AGENTS.md específico do agente.
3. Consultar skills relevantes antes de executar tarefas especializadas.
4. Consultar a memória antes de tomar decisões que dependam de contexto anterior.
5. Não armazenar informações sensíveis desnecessariamente.
6. Não modificar arquivos fora do escopo da tarefa.
7. Não fazer commit de segredos.
8. Testar alterações antes de finalizar.
9. Registrar decisões importantes.
10. Utilizar handoff quando uma tarefa for delegada.

## Memória

A memória persistente deve ser acessada através do módulo ai-memory.

Nunca acessar diretamente o banco de memória a partir de um agente.

## Skills

Skills são capacidades reutilizáveis.

Um agente deve carregar somente as skills necessárias para sua tarefa.

## Git

Alterações devem ser pequenas, rastreáveis e relacionadas à tarefa.

Nunca executar operações destrutivas sem confirmação.

## Handoff

Toda delegação entre agentes deve possuir:

- objetivo
- contexto
- entrada
- saída esperada
- restrições
- critérios de conclusão

## Segurança

Segredos, tokens, credenciais e dados pessoais não devem ser armazenados
em memória persistente ou commits.


Esse arquivo funciona como a constituição do sistema.

Exemplo:

# CEO Agent

## Responsabilidade

O CEO é o agente responsável por:

- entender objetivos do usuário
- decompor problemas
- criar plano de execução
- delegar tarefas
- acompanhar handoffs
- resolver conflitos
- validar resultados
- decidir quando uma tarefa está concluída

## Não fazer

O CEO não deve implementar código complexo quando existe um
Developer disponível para executar a tarefa.

Não deve delegar tarefas sem contexto suficiente.

Não deve considerar uma tarefa concluída apenas porque um agente
afirmou que terminou.

## Delegação

Antes de delegar:

1. identificar o tipo da tarefa
2. identificar o agente adequado
3. consultar memória relevante
4. consultar skills relevantes
5. criar handoff

## Finalização

Uma tarefa somente pode ser considerada concluída quando:

- resultado esperado foi produzido
- testes foram executados quando aplicável
- erros conhecidos foram tratados
- documentação necessária foi atualizada

04. AGENTS.md do Developer

O Developer recebe uma responsabilidade bem mais operacional.

# Developer Agent

## Responsabilidade

Responsável por:

- implementar funcionalidades
- corrigir bugs
- escrever testes
- refatorar código
- revisar implementação técnica
- atualizar documentação técnica

## Antes de implementar

1. Ler AGENTS.md global.
2. Ler este arquivo.
3. Ler o handoff recebido.
4. Consultar memória relacionada ao projeto.
5. Identificar skills necessárias.
6. Inspecionar código existente.

## Durante implementação

- respeitar arquitetura existente
- evitar alterações desnecessárias
- reutilizar componentes existentes
- escrever testes
- não introduzir dependências sem necessidade

## Antes de finalizar

Executar:

- testes
- lint
- type checking quando disponível

Depois retornar:

- arquivos modificados
- resumo
- testes executados
- problemas encontrados
- decisões importantes
- próximo passo recomendado

06. Integração ai-memory

Aqui está uma parte importante.

Eu não deixaria:

Agent → PostgreSQL


e sim:

Agent
  ↓
MemoryManager
  ↓
ai-memory
  ↓
Store / Retriever
  ↓
Database / Vector DB


API conceitual:

memory.remember(...)
memory.recall(...)
memory.update(...)
memory.forget(...)
memory.promote(...)


Exemplo:

await memory.remember(
    user_id="user_123",
    content="O projeto utiliza FastAPI.",
    memory_type="fact",
    importance=0.8,
)


Recuperação:

memories = await memory.recall(
    user_id="user_123",
    query="Qual framework backend o projeto utiliza?"
)


O contexto recuperado pode entrar no agente:

User Request
     │
     ▼
Memory Recall
     │
     ▼
Relevant Context
     │
     ▼
Agent
     │
     ▼
Response

A ideia central é que o sistema tenha quatro fontes diferentes de inteligência:

AGENTS.md → identidade, responsabilidades e regras.
SKILL.md → conhecimento operacional reutilizável.
ai-memory → experiência e contexto acumulados.
MCP → acesso às ferramentas e ao mundo externo.

E o CEO funciona como orquestrador, transformando uma solicitação do usuário em tarefas, distribuindo-as através de handoffs e consolidando os resultados.

Essa estrutura também cria um caminho interessante para evolução: experiência → memória → padrão → skill/regra → comportamento permanente do sistema.
